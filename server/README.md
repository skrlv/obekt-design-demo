# Локальный каталог с настоящим сохранением

Из корня проекта: `node server/server.mjs`, затем открыть <http://127.0.0.1:4191/?backend=1>. Нужен Node.js 22+. Установка зависимостей не требуется. Другой порт: `PORT=4192 node server/server.mjs`.

**Режим запуска.** Параметр `?backend=1` подключает интерфейс к API. Адрес без него показывает независимую браузерную демонстрацию, даже если файлы раздаёт Node-сервер. Корзина, избранное и сравнение в обоих режимах остаются в браузере; сервер хранит только каталог.

GET `/api/products` возвращает `{products, demo: true, storage: "local-file"}`. POST `/api/products` создаёт товар; PUT `/api/products/:id` заменяет весь товар без изменения ID; DELETE `/api/products/:id` удаляет. POST/PUT принимают JSON и возвращают `{product, demo: true}`; DELETE — `{deleted, demo: true}`. Проверка работы: GET `/api/health`.

Файл `server/data/products.json` создаётся после первого изменения. Он переживает перезапуск; файл исключён из Git. Начальные данные импортируются из `catalog.mjs`. Для сброса остановите сервер и удалите этот файл.

Сервер привязан только к 127.0.0.1. Любой процесс и пользователь этого компьютера, способный обратиться к локальному порту, может читать и менять демонстрационный каталог; отдельного права администратора нет. Это граница локальной демонстрации, а не серверная авторизация. Изменения проверяют Origin и Sec-Fetch-Site; каталог валидируется, размер запроса ограничен, произвольные файлы не раздаются. Панель не имеет пользователей и ролей: этот запуск предназначен для локальной демонстрации одного оператора. Не открывайте его во внешнюю сеть. Для рабочего магазина нужны серверная авторизация, база, резервные копии, реальные данные и интеграции.

На GitHub Pages сервер не запускается. Публичная панель изменяет только данные браузера; она не меняет опубликованный каталог других посетителей. Оплата, доставка, реальные заказы и клиентские данные не подключены ни в одном режиме.

Запускайте только один процесс для одного файла каталога: очередь и атомарная замена файла защищают записи внутри одного процесса, но не согласуют несколько независимых серверов.

Проверка: `node --test server/server.test.mjs`. Проверяются CRUD, сохранение после перезапуска, конкурентное создание одного ID, валидация, недоступность служебных файлов, Origin/Sec-Fetch-Site/Host, неверный JSON, лимит тела, повреждённое хранилище и отказ записи. Тестовые файлы создаются во временной папке и удаляются автоматически.
