# ОБЪЕКТ · 2.0.0

Демонстрационный интернет-магазин вымышленного бренда мебели и света: от поиска предмета и сравнения до выбора отделки, корзины и управления каталогом.

Демо: [skrlv.github.io/obekt-design-demo](https://skrlv.github.io/obekt-design-demo/). Репозиторий: [skrlv/obekt-design-demo](https://github.com/skrlv/obekt-design-demo). Версия публичной страницы проверяется в `version.json` и метаданных `application-version`; доказательства публикации и проверок — в `RELEASE.md`.

## Возможности

- Шесть исходных предметов: категории, поиск по имени и типу, материал, цвет, максимальная цена и сортировка. Фильтры работают совместно.
- Сравнение до четырёх предметов: изображения, цены, размеры, материалы и цвета.
- Избранное и отдельный фильтр подборки; до 100 предметов.
- Карточка с выбором цвета и материала. Разные отделки становятся отдельными строками корзины. Фото остаётся иллюстративным и не меняется при выборе цвета.
- Корзина: количество, удаление, пересчёт по текущим ценам, до 20 единиц одной отделки и 60 разных конфигураций.
- Тестовый просмотр заказа: не создаёт заказ, не запрашивает личные или платёжные данные, не списывает деньги.
- Панель: создание, изменение, скрытие, удаление, JSON-экспорт и сброс браузерного каталога. До 200 товаров; картинки выбираются из локальных иллюстраций.
- Сохранение и обновление между вкладками. Повреждённые данные восстанавливаются, недоступное хранилище не мешает работе текущей страницы и сопровождается предупреждением.
- Адаптивная сетка, подписанные поля, нативные диалоги, Escape, возврат фокуса, режим reduced motion. Без JavaScript доступна исходная витрина.

## Границы демонстрации

На GitHub Pages каталог, избранное, сравнение и корзина хранятся только в `localStorage` этого браузера (`obekt-studio-v2`). Изменения панели не видны другим посетителям и не меняют файлы репозитория. Очистка данных сайта сбрасывает состояние. Это открытая демонстрационная панель без серверной авторизации.

Имена, цены, размеры, отделки и характеристики условные. Фотографии иллюстрируют интерфейс и не подтверждают свойства предметов, наличие, производство или права на бренд. Реальных клиентов, отзывов, продаж и заказов в проекте нет. Оплата, доставка, склад, почта и CRM не подключены.

Отдельный локальный Node-сервер действительно сохраняет каталог в файл, но не выполняется на Pages. Он доступен только на этом компьютере, без пользователей и ролей. Любой локальный процесс с доступом к порту может менять демокаталог. Защита Origin/Host и границ файлов не является авторизацией администратора. Корзина и подборки остаются браузерными в обоих режимах.

## Запуск и проверки

Нужны Node.js 22+ и Python 3 для статического запуска. Внешних зависимостей приложения нет.

```sh
npm start
```

Локальное браузерное демо: `http://127.0.0.1:4183/`. Открытие `index.html` через `file://` не поддерживает модули.

```sh
npm run check
npm test
npm run build
```

`npm test` проверяет каталог, отделки, корзину, валидацию, серверный CRUD, сохранение, конкуренцию записей и границы доступа. `npm run build` создаёт `_site/` по списку публичных файлов; сервер, тесты и данные в артефакт не включаются.

Для сохранения каталога на локальном сервере:

```sh
npm run start:server
```

Открыть `http://127.0.0.1:4191/?backend=1`. Параметр обязателен; без него работает отдельное браузерное демо. Файл `server/data/products.json` создаётся после первого изменения. Подробные API, права, сброс и ограничения: [server/README.md](server/README.md). Не запускайте два процесса с одним файлом данных.

Дополнительная воспроизводимая проверка Chromium, включая локальный сервер через интерфейс:

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm start
# в другом терминале из каталога проекта:
npm run test:ui
```

Playwright нужен только для этой проверки; приложение и Node-тесты работают без него. Скриншоты и JSON-результаты сохраняются в `qa-output/` (или пути `QA_OUTPUT`). При установленном Playwright в другом месте можно передать путь к его `index.mjs` через `PLAYWRIGHT_MODULE`. Проверка создаёт временную изолированную браузерную сессию и временный серверный каталог, затем закрывает их.

## Сценарий на две минуты

1. В коллекции выберите «Сидеть», материал «Ткань», цвет «Графит», цену до 40 000 и поиск «кресло». Останется «Мягкая линия».
2. Сбросьте фильтры. Добавьте два предмета в сравнение и проверьте таблицу. Пятый предмет при четырёх выбранных не добавится.
3. В карточке «Мягкая линия» выберите «Песочный / Букле», добавьте в корзину. Добавьте «Слоновая кость / Ткань»: появятся две строки.
4. Измените количество и откройте демо-заказ. Корзина сохранится; заказ и платёж не создаются.
5. В панели измените тестовую цену или добавьте предмет. Перезагрузите страницу. На Pages правка останется только в вашем браузере; в режиме `?backend=1` цена сохраняется и после перезапуска локального сервера.

## Структура

- `index.html`, `styles.css`, `app.js` — интерфейс и браузерные действия.
- `catalog.mjs` — исходные товары, фильтры, валидация и расчёт.
- `assets/`, `ASSETS.md` — локальные изображения, происхождение и лицензия.
- `server/` — отдельное локальное API и тесты.
- `tests/` — логика и воспроизводимые проверки интерфейса.
- `scripts/build.mjs` — сборка статического артефакта.
- `CASE.md` — обновление существующего кейса ОБЪЕКТ; новый дублирующий кейс не требуется.
- `.github/workflows/pages.yml` — проверка и публикация.

## Публикация

Отдельный публичный репозиторий `skrlv/obekt-design-demo`, ветка `main`, базовый путь `/obekt-design-demo/`. Все ресурсы используют относительные пути. Официальные GitHub Actions: checkout, setup-node, upload-pages-artifact и deploy-pages; артефакт `_site/`. Workflow проверяет исходники, запускает Node-тесты и собирает сайт перед развёртыванием. GitHub Pages не запускает Node-сервер и не хранит общий каталог. Основа: [официальная документация Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Изображения перенесены из прежнего проекта с сохранёнными ссылками на Unsplash. Источники и ограничения перечислены в [ASSETS.md](ASSETS.md). Системные шрифты не требуют внешних запросов.
